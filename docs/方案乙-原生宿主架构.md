# 方案乙 · 自建轻量 Kotlin 原生宿主（Vue 前端零改动）

> 状态：2026-09-06 立项。解决 5+App 黑盒在分区存储/SAF/系统能力上的结构性短板。

## 为什么是乙
- 前端是大型富交互 SPA（KaTeX/ECharts/three/AI 对话），Vue 是强项，保留；
- Android 系统能力（SAF 选文件夹、MediaStore 公共写、系统分享、返回键）必须原生实现，Web 沙箱做不了；
- 方案 = 单个 Activity + System WebView + JSBridge，加载现有 Vue 构建产物；业务与页面零改动。

## JS↔原生桥协议（window.xcnative）

| 方法 | 入参 | 返回/回调 | 说明 |
|---|---|---|---|
| appInfo() | | JSON串 | {versionName, versionCode, sdk, manufacturer, model} |
| toast(msg) | string | - | 原生 Toast |
| clipboardSet(t) | string | bool | 写系统剪贴板 |
| clipboardGet() | | string/空 | 读剪贴板 |
| shareText(text[,title]) | | bool | ACTION_SEND 文本 |
| shareFile(name, base64, mime) | | bool | 先 MediaStore.Downloads 落盘再分享 |
| saveImage(dataUrl, name) | | JSON | 解码→MediaStore.Pictures(行测AI导出)；返回{ok,where,displayPath} |
| saveText(name, text) | | JSON | MediaStore.Downloads(Download/行测AI导出) |
| saveBinary(name, base64, mime) | | JSON | 同上，用于 md/docx/pdf |
| pickFolder(reqId) | number | 异步：window.__xcOnPick(reqId, treeUri, name, null/err) | SAF ACTION_OPEN_DOCUMENT_TREE + 持久授权 |
| writeIntoFolder(treeUri, name, base64, mime, reqId) | | 异步 __xcOnWrite | DocumentsContract.createDocument + OutputStream |
| fileChooser 原生 | WebChromeClient | 系统选文件 | <input type=file> 可用（相册/文件） |
| 返回键 | onBackPressed→JS | 页面 __xcConsumeBack() 返回 true 则拦截 | 与 Esc 同语义，未消费再退出 |

## 前端接入（platform.js）
- 新增检测 isNativeHost()（window.__XC_HOST__ 由宿主注入）；hostKind() 返回 'nativehost'；
- 剪贴板/分享/震动/原生toast/返回键/版本号 在 nativehost 下直连 xcnative；
- 文件保存：downloadOut/nativeSave 的写入分支在 nativehost 下改走 saveImage/saveText/saveBinary + pickFolder/writeIntoFolder（业务调用方不变）；
- plus 分支保留：同一份前端仍可打 5+App 包（A/B 双轨）。

## 构建与运行
1. 同步资源：powershell -ExecutionPolicy Bypass -File _同步到原生宿主.ps1（把 xingce-app-shell 产物拷入 assets/www 并剥离 PWA）；
2. 编译安装：gradle :app:assembleDebug 后用 adb 装到 android15 AVD；
3. 验证链路：导出备份(SAF/分享)、截图入相册、md/docx 入 Download、系统选图、返回键。
